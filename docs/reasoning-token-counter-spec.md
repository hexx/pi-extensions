# 仕様書：`reasoning-token-counter.ts` — Reasoning トークン常時表示拡張

**状態**: 確定（grill-with-docs セッション合意）
**関連**: [CONTEXT.md](../CONTEXT.md)（用語集）

## 1. 背景と目的

pi のビルトインフッターはセッションのトークン統計（↑input / ↓output / キャッシュ / cost / context%）を表示するが、**Reasoning（思考）トークンの内訳を表示しない**。Reasoning モデルを使うと出力トークンの相当部分が「思考」に消費されるため、ユーザーは「今のターンでどれだけ考えたか」「セッション全体でどれだけ思考に使ったか」を知りたい。

本拡張は pi の extension API（イベント購読 + `ctx.ui.setStatus`）のみでこれを実現する。**ツール・コマンド・設定は一切追加しない**（常時ONの表示拡張であり、読み込み元から外せば無効化できる）。

## 2. 決定済みの基本方針（Q&A の結論）

grill-with-docs セッション（2ラウンド）の結論。すべて容易に反転可能な決定のため、ADR は作成しない（仕様書に根拠を記録する）。

| # | 決定 | 理由の要約 |
|---|------|-----------|
| Q1 | 表示場所は**フッターの拡張ステータス行**（`ctx.ui.setStatus`） | ビルトインフッターと共存し、常時表示に最適。`setFooter` による全置換はビルトイン機能の自前実装が必要 |
| Q2 | 表示スコープは**今ターン＋セッション累計の両方** | 「今どれだけ考えたか」と「セッションでどれだけ思考したか」は別の価値 |
| Q3 | **ライブ推定はしない**。プロバイダが報告する `usage.reasoning` のみ使用 | ストリーム末尾まで usage は届かないため、リアルタイム値を出すには thinking テキストの文字数推定が必要になるが、誤差を出す価値がない。ストリーミング中はスピナー表示 |
| Q4 | リポジトリに**単一ファイル** `reasoning-token-counter.ts` ＋ README ＋ 本仕様書 | 既存拡張（brave / atlassian / block-push-to-main）と同じ構成 |
| Q5 | 値が無いとき（`undefined`）は**非表示** | 「考えなかった」と誤読されるのを防ぐ |
| Q6 | 数値は**ビルトインフッターと同じ k/M 省略表記**、`thinking` アイコン＋`/` 区切り | フッターは1行・幅制限付きのため統一ルールが自然 |
| Q7 | 値が `0` のときも**非表示**（Q5 と同扱い） | OpenAI 系は thinking off で `0`、Anthropic は `undefined` を返すため、このルールで両プロバイダの挙動が揃う |
| Q8 | **トグルコマンドなし**（常時ON） | 要望は「常に表示」。コマンド追加は後付け容易 |
| Q9 | ストリーミング中は**直前ターンの確定値を出し続け**、今ターンの実測値が届いたら置き換える | 当初はスピナー表示（a）を採用したが、実利用で視認性が低かったため改訂。直前ターンの値を「今ターン」と誤読するリスクはあるが、実測値が入り次第即座に置き換わる |
| Q10 | 今ターンのみ**出力比（%）を表示** `thinking 1.2k (73%) / 45k`。分母は出力トークン、出力 100 未満のターンでは省略 | 出力比は思考の濃さの指標で、thinking level 調整や overthinking 検知に使える。全体（input+output+cache）を分母にすると input が支配的で無意味。セッション累計への % はモデル変更・コンパクションで解釈が曖昧になるため付けない |

### 前提（確認済みの動作基準）

- 集計ルールは**ビルトインフッターと同基準**: assistant / toolResult メッセージの `usage` に加え、compaction / branch_summary エントリの `usage`（サマリ生成 LLM 呼び出し分）もセッション累計に含める
- `aborted` / `error` のアシスタントメッセージも、usage があれば集計に含める（ビルトインと同じ）
- `/new` で 0 にリセット、`/resume` では全エントリをリプレイして再集計
- ステータスキーは `"reasoning"`（フッターでは複数拡張のキーがアルファベット順に並ぶ）

## 4. 表示仕様

フッターの拡張ステータス行（3行目）に常時表示する。

| 状態 | 表示 | 補足 |
|------|------|------|
| アイドル・今ターン値あり | `thinking 1.2k (73%) / 45k` | 左=今ターン（accent）＋出力比、右=セッション累計（dim） |
| アイドル・今ターン値なし | `thinking 45k` | 累計のみ。dim で表示 |
| ストリーミング中（実測値なし） | `thinking 1.2k (73%) / 45k` | 直前ターンの確定値＋その出力比を出し続ける。前回値が無い場合は累計のみ/非表示（スピナーは使わない） |
| ストリーミング中（実測値あり） | `thinking 1.2k (73%) / 45k` | 今ターンの実測値（確定分＋ライブ値）とその出力比が入り次第置き換わる。実質ストリーム末尾で確定 |
| 値が一切ない（非対応プロバイダ・thinking off） | （非表示） | ステータス自体をクリア |

- 出力比 = `今ターンの Reasoning ÷ 今ターンの出力トークン × 100`（整数% に丸め）。**表示する値と対になるデータ**（同じターンの出力）から計算する。ストリーミング中に直前ターンの値を出している間は直前ターンの出力比を添える
- 出力 100 トークン未満の小さいターンでは比率が不安定なため **% を省略**。`reasoning > output` になる値（プロバイダ異常）や 0% に丸まる極小比率も省略
- 数値の省略ルールはビルトインフッターの `formatTokens` と同じ: 1k 未満は生値 / 1万未満は小数1桁の k / 100万未満は丸め k / 以降 M
- 色: 今ターン（進行中の情報）は `accent`、セッション累計（背景情報）は `dim`。累計のみの場合は全体を `dim`
- 幅超過時の切り詰め・改行サニタイズはビルトインフッターが行う（`setStatus` の仕様）

## 5. データソースと集計ルール

### 5.1 `usage.reasoning` と出力比

`Usage.reasoning?: number` は Reasoning トークン数（`output` の内数）。プロバイダが報告する場合のみ設定される。

- **OpenAI 系**: `completion_tokens_details.reasoning_tokens` から設定。報告がない場合は `0` になる
- **Anthropic**: thinking ブロックのトークンから設定。thinking がないターンでは `undefined`
- 非対応プロバイダ: `undefined`

本拡張は `undefined` と `0` を同じ「値なし」として扱う（Q5/Q7）。これにより、値が表示される = モデルが実際に思考した、が保証される。

**出力比（%）** は今ターンの `reasoning ÷ output`（Q10）。出力トークンも `message_end` で今ターンに加算して保持し、表示する値と対になるデータから計算する。

### 5.2 セッション累計の対象

ビルトインフッターの集計（`usage-totals.ts` 相当）と同じ対象:

1. アシスタントメッセージの `message.usage.reasoning`
2. toolResult メッセージの `message.usage.reasoning`（ツール内のネスト LLM 呼び出し。例: サブエージェントの思考）
3. compaction / branch_summary エントリの `entry.usage.reasoning`（サマリ生成の思考）

### 5.3 イベント処理

| イベント | 動作 |
|----------|------|
| `session_start` | `getEntries()` のリプレイで累計を再集計。今ターン・ライブ値を 0 にリセット |
| `turn_start` | 今ターンを 0 にリセット。直前ターンの確定値を表示し続ける（スピナーは使わない） |
| `message_update` | アシスタントメッセージの `usage.reasoning` が届いたらライブ表示に反映（加算はしない） |
| `message_end` | assistant / toolResult の `usage.reasoning` を今ターンに、`usage.output` を今ターン（出力比の分母）に加算。ライブ値をクリア |
| `turn_end` | 直前ターン値（Reasoning・出力）を今ターンの確定値で更新。累計を全エントリから再集計して表示を確定 |
| `session_compact` | リプレイで累計を再集計（サマリの usage を含めるため） |

**累計の導出方式**: セッション累計は**加算でなく、常に永続化済みエントリからの再集計で導出**する（`turn_end` / `session_start` / `session_compact` で `getEntries()` をスキャン。ビルトインフッターと同じ方式）。`message_end` で累計に加算しないのは、イベントの再発火などが起きても二重加算しないため。今ターン値はライブ表示に必要なため `message_end` での加算とする（再発火時は次の実ターンで正規化される）。`model_select` / `thinking_level_select` は購読不要 — usage 駆動のため自動追従する。

## 6. エッジケース

| ケース | 挙動 |
|--------|------|
| thinking off / 非対応モデル | usage に値が無い → 非表示 |
| ストリーミング中（usage 未到着） | 直前ターンの確定値＋その出力比を表示（前回値が無ければ累計のみ/非表示） |
| 出力が少ないターン（100 未満） | % を省略（比率が不安定なため） |
| `reasoning > output`（プロバイダ異常） | % を省略 |
| 極小比率（丸めて 0% になる） | % を省略（例: 出力300で reasoning 1） |
| ターン内に複数メッセージ（ツール呼び出し含む） | `message_end` ごとに加算され、ターン値は合算される |
| `aborted` / `error` | usage があれば集計（ビルトインと同基準） |
| コンパクション後 | エントリは残るためリプレイで累計維持 |
| `/resume` / `/fork` | リプレイで再集計 |
| 幅が狭いターミナル | フッターが切り詰め |
| JSON / print モード | `ctx.hasUI` ガードで更新自体をスキップ（TUI / RPC のみ動作。RPC では通知として送信） |

## 7. 受け入れ基準

1. フッターに `thinking {今ターン} ({出力比}%) / {累計}` が表示される（Reasoning モデル使用時）
2. ストリーミング中は直前ターンの値が表示され、今ターンの実測値が届いたら置き換わる
3. 出力比は出力 100 トークン未満のターンでは省略される
4. 値が無いモデル・thinking off では何も表示されない
5. `/new` で累計が 0 に戻る
6. セッションを再開（`/resume`）しても累計が復元される
7. 既存のフッター表示（pwd・トークン統計・context%）が壊れない
8. ビルトイン拡張例（`status-line.ts`）と共存して両方のステータスが表示される

## 8. v1 スコープ外

- ライブ推定（thinking テキストの文字数ベース）— Q3 で不採用
- ターンごとの履歴表示・グラフ
- Reasoning トークン数のコスト換算表示
- **セッション累計の出力比（%）** — モデル変更・コンパクションが混ざり解釈が曖昧になるため（Q10）
- トグルコマンド・設定項目 — Q8 で不採用（後付け容易）
- セッション累計の永続化（セッションファイルへの保存）— リプレイで再計算可能なため不要

## 9. README 追加セクション（実装時に転記する草案）

### `reasoning-token-counter.ts` — Reasoning トークン数をフッターに常時表示

モデルが消費した Reasoning（思考）トークン数をフッターの拡張ステータス行に常時表示します。ビルトインフッターにない「推論トークンの内訳」を補完します。

- **表示**: `thinking 1.2k / 45k`（左=直近ターン、右=セッション累計。ストリーミング中は `thinking …`）
- **データ**: プロバイダが報告する `usage.reasoning` のみを使用（推定なし）。OpenAI 系・Anthropic 対応
- **挙動**: 値が無いとき（非対応モデル・thinking off）は非表示。`/new` でリセット、`/resume` で再集計
- **設定**: なし（常時ON。外したい場合は読み込み元から外す）
- 設計: `docs/reasoning-token-counter-spec.md`・`CONTEXT.md` を参照
