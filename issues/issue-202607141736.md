# 課題解決プロンプト: pi coding agent 用 Brave Search extension の作成

## 1. 役割定義 (Persona)
あなたは高度なソフトウェアエンジニアおよび pi coding agent の拡張機能（extension）開発のエキスパートです。以下のコンテキストとゴールを基に、正確かつ効率的に pi 用の Brave Search 拡張機能を設計・実装してください。

## 2. 背景・前提条件 (Context)
- **現状発生している問題**: pi coding agent には Web 検索（Brave Search）を LLM から直接呼び出せる仕組みがなく、外部の MCP サーバー（Brave Search MCP Server）を活用できていない。Codex 環境ではすでに同様のサーバーが LiteLLM 上に用意されており、同様の機能を pi でも利用できるようにしたい。
- **再現手順 / 利用想定**:
  1. 利用者の環境で `LITELLM_API_KEY` に自身の LiteLLM API Key が設定されていること。
  2. Codex 向けには以下の環境変数設定がドキュメント化されている。
     ```bash
     export LITELLM_MCP_AUTH_HEADER="Bearer ${LITELLM_API_KEY}"
     ```
  3. Codex の `~/.codex/config.toml` には以下の MCP サーバー設定が追加されている。
     ```toml
     [mcp_servers.brave_search]
     url = "https://api.llm-gateway.kurisu.nico/brave_search/mcp"
     env_http_headers = { "x-litellm-api-key" = "LITELLM_MCP_AUTH_HEADER" }
     enabled = true
     ```
- **関連ファイル/コード**:
  - 実装対象: 新規作成する pi 拡張機能ファイル（例: `.pi/extensions/brave-search.ts` または `~/.pi/agent/extensions/brave-search.ts`）
  - 参照ドキュメント: `docs/extensions.md`（pi の拡張機能 API: `registerTool`, `ExtensionAPI`, `ExtensionContext` など）
  - エンドポイント: `https://api.llm-gateway.kurisu.nico/brave_search/mcp`
  - 認証: `LITELLM_API_KEY`（Bearer トークン）を `Authorization` または `x-litellm-api-key` ヘッダで送信

## 3. 解決すべきゴール (Goal & Objective)
- [ ] pi の拡張機能として `brave_search` ツールを登録し、LLM が検索クエリを渡して Web 検索結果を得られるようにする。
- [ ] 認証に `LITELLM_API_KEY` を使用し、Codex 向けと同様の `https://api.llm-gateway.kurisu.nico/brave_search/mcp` エンドポイントへ適切なヘッダ（`Authorization: Bearer <LITELLM_API_KEY>` または `x-litellm-api-key`）でリクエストを送る。
- [ ] 環境変数が未設定の場合は、`ctx.ui.input` で API Key の入力を促すか、明確なエラーメッセージを通知（`ctx.ui.notify`）する。
- [ ] ツールのパラメータ（検索クエリ `query`、`count` などのオプション）を `typebox`（`Type.Object` など）で定義し、MCP 呼び出しまたはプロキシ経由の検索結果を LLM が読める `content` 形式で返す。
- [ ] 拡張機能の配置場所（`.pi/extensions/` または `~/.pi/agent/extensions/`）と `/reload` でのホットリロード、`pi -e ./brave-search.ts` での動作確認手順を README またはコメントに記載する。
- [ ] 既存の pi 拡張機能のスタイル（`ExtensionAPI` の `on` / `registerTool` パターン）に従い、エラーハンドリング（ネットワーク失敗、認証失敗）を適切に実装する。

## 4. 期待する成果物 (Output Format)
- 修正が完了したコード一式（新規拡張機能ファイル `brave-search.ts` および必要な設定・README 追記）
- 修正理由とアプローチの簡潔な解説（Codex の MCP 設定を pi の `registerTool` ベースの拡張機能にどうマッピングしたか）
- 動作確認またはテストの実行結果（`pi -e ./brave-search.ts` での起動ログ、実際の検索呼び出しの成功例）
